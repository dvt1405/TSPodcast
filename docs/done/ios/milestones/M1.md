## 1. Mục tiêu

Cuối M1, người dùng cài mới đi được hết luồng **Onboarding (4 trang) → chọn ≥ 3 danh mục → Main (TabView) → Home**. Mở lại app thì vào thẳng Home. Cụ thể:

1. `shared` có kho key-value bền vững (không dùng `UserDefaults`) giữ các cờ `OnboardingFinished`, `HasSelectFavouriteCategory`, `ListFavouriteCategory`, cache đĩa `CategoryRes` (E9) và cache đĩa trending 15 phút (`cachedTrending*`), cùng logic start destination, luật chọn ≥ 3 danh mục và một `HomeFeed` gom các lời gọi của Home (đúng `since`/`cat`/fallback của `MainViewModel`, lọc explicit theo D6). Tất cả có unit test trong `commonTest`.
2. App iOS: SwiftUI `TabView` 3 tab **Yêu thích / Khám phá (mặc định) / Tìm kiếm**, **không có Radio**. Mỗi tab có `NavigationStack` riêng. Có chỗ (slot) cho MiniPlayer nằm trên tab bar.
3. Home/Discover đủ 5 section theo đúng thứ tự Android, cùng footer attribution Podcast Index. Mỗi section có trạng thái loading (shimmer), empty và error kèm nút "Tải lại" riêng ([Sửa]). Có pull-to-refresh.
4. Ảnh cover tải bằng loader gửi header `User-Agent` dạng trình duyệt. Ảnh `http://` được xử lý theo setup-and-build §3.3 (không bật `NSAllowsArbitraryLoads`).
5. String Catalog `Localizable.xcstrings`: `vi` là ngôn ngữ nguồn, có thêm `en`.
6. Có target unit test (`TSPodcastTests`) và XCUITest (`TSPodcastUITests`) trong `project.yml`. XCUITest phủ mọi luồng tương tác của M1 và là bộ regression cho các milestone sau.
7. Màn debug `Trending (debug)` của M0 bị gỡ.

## 4. Quyết định kỹ thuật cho M1 (developer không cần hỏi lại)

### 4.1 Kho key-value trong `shared` (architecture §3.3)

- `interface KeyValueStore` trong `commonMain`, API `suspend`: `getString/putString`, `getBoolean/putBoolean`, `getLong/putLong`, `remove`, `clear`. Một implementation duy nhất trong `commonMain`, đọc/ghi một **file** (không dùng `NSUserDefaults`, `multiplatform-settings` hay `@AppStorage`), để không phát sinh required-reason API `UserDefaults` trong `PrivacyInfo.xcprivacy`.
- Thứ tự ưu tiên: **DataStore Preferences KMP** (`androidx.datastore:datastore-preferences-core`, file `ts_prefs.preferences_pb`) nếu có bản được build bằng Kotlin ≤ 2.2.0 (kiểm `kotlin-stdlib` trong file `.module` trên Maven Central như cách làm ở M0 T1). Nếu không có: tự viết store JSON bằng Okio (file `ts_prefs.json`, ghi file tạm rồi `atomicMove`, `Mutex` cho mọi thao tác). Ghi lựa chọn và lý do vào `progress.md`.
- Đường dẫn file do Swift truyền vào: `Application Support/ts_prefs.*` (tạo thư mục nếu chưa có). Test dùng `okio-fakefilesystem` hoặc thư mục tạm.
- File hỏng hoặc không đọc được → coi như store rỗng (không crash), ghi log một lần.
- `AppPreferences` (lớp bọc có kiểu) dùng **đúng tên key Android**: `OnboardingFinished`, `HasSelectFavouriteCategory`, `ListFavouriteCategory`, `CategoryRes`, `cachedTrending`, `lastUpdateTrending`, `cachedTrending_<cat>`, `lastUpdateTrending_<cat>`. Thêm một key mới cho D6: `AllowExplicitContent` (Boolean, mặc định `false`).
- `SharedGraph` nhận thêm tham số đường dẫn store (ví dụ `SharedGraph(credentials, config, preferencesPath)`; constructor test nhận thêm `KeyValueStore`). Swift vẫn tạo **một** graph mỗi process.

### 4.2 Logic dùng chung mới trong `shared`

- `StartDestination { Onboarding, SelectFavouriteCategory, Main }` và `suspend fun AppPreferences.startDestination()` theo bảng §3.
- `OnboardingPreferences`/`FavouriteCategories`: `MIN_FAVOURITE_CATEGORIES = 3`, `canSave(count)`, `save(categories)` trả `false` và **không ghi gì** khi < 3; khi đủ thì ghi `ListFavouriteCategory` (mỗi mục `isFavourite = true`) rồi `HasSelectFavouriteCategory = true`. `favouriteCategoryIds(): String?` trả id sắp tăng dần nối bằng `","`, `null` khi chưa có.
- `GetCategories`: thêm tầng đĩa theo bảng §3 (mạng OK → ghi `CategoryRes`; lỗi → memory gần nhất → đĩa → asset). Asset vẫn sinh từ `coreApi/src/main/assets/categories.json` (M0).
- `GetTrendingPodcasts`: thêm tầng đĩa theo bảng §3. Key memory giữ như M0 (theo `cat` đã chuẩn hoá); key đĩa `cachedTrending` khi `cat` rỗng, `cachedTrending_<cat>` khi có. JSON hỏng trên đĩa → bỏ qua, gọi mạng. Không lưu kết quả `Error`.
- `HomeFeed` (property của `SharedGraph`), mọi hàm `suspend` trả `TSDataState`, dùng `EpochClock` để tính `since`:
  - `trendingSections(favouriteCatIds: String?)`: gọi **song song** E1 trending (`since = now − 7 ngày`) và E1 yêu thích (`since = now − 10 ngày`, `cat = favouriteCatIds`), áp dụng ba nhánh fallback ở §3, trả một kết quả chứa `trending` và `forYou`, mỗi cái là `TSDataState<List<Podcast>>`.
  - `music()` (E6, `max = 40`), `live()` (E2, `max = 100`), `recent(favouriteCatIds)` (E5, `max = 100`, `lang = "vi"`, `notcat = null`).
  - Lọc explicit (D6) **sau** blacklist, khi `AllowExplicitContent == false`: bỏ `Podcast.explicit == 1` và `LiveEpisode.explicit == 1`. Trending (E1) và recent feeds (E5) **không trả field `explicit`** (xem `podcasts/src/debug/assets/Trending.json`, `RecentFeeds.json`), nên item của hai endpoint này luôn qua bộ lọc. Đây là giới hạn của API, ghi vào handoff (§7).
  - Không gọi E3/E4.
- `HtmlText.toPlainText(html: String?): String` trong `commonMain`: bỏ tag, `<br>`/`</p>`/`</li>` thành xuống dòng, giải mã entity (`&amp; &lt; &gt; &quot; &#39; &apos; &nbsp;`, `&#NNN;`, `&#xHH;`), gộp khoảng trắng thừa, trim. Dùng cho mô tả ở Home (Android dùng `HtmlCompat.fromHtml`).
- `SharedConstants.USER_AGENT_WEB_VALUE` trong `commonMain`, giá trị **trùng từng ký tự** với `sharedResources/.../SharedConstants.kt`. Swift chỉ đọc hằng số này, không hardcode.
- `interface AnalyticsTracker { fun trackScreen(screen: String, params: Map<String, String>); fun trackEvent(name: String, screen: String) }`. Không có thuộc tính `device_id`.
- Swift không dùng SKIE (giữ quyết định M0). Swift gọi `suspend fun` qua bridge `async`; state UI nằm trong các `@MainActor @Observable final class` phía Swift.

### 4.3 Cấu trúc app iOS

- Thư mục trong `iosApp/TSPodcast/`: `App/` (`TSPodcastApp`, `AppEnvironment` giữ `SharedGraph` + `AppPreferences`, `RootView`, `LaunchOptions`), `Design/` (màu, shimmer), `Images/` (`ArtworkLoader`, `ArtworkImage`), `Onboarding/`, `Categories/`, `Main/` (`MainTabView`, `MiniPlayerSlot`), `Home/`, `Favourite/`, `Search/`, `Detail/` (stub), `Resources/` (`Localizable.xcstrings`, `Assets.xcassets`). Xoá `Debug/TrendingDebug*`.
- `RootView` đọc `startDestination()` một lần khi launch. Trong lúc chờ (vài ms) chỉ hiện nền trơn, không spinner. Chuyển màn bằng state của root, không dùng back stack: không quay lại được Onboarding từ màn chọn danh mục, giống Android (`startDestination` đổi thì NavHost reset).
- `MainTabView`: `TabView(selection:)` với `.tabItem` + `.tag(AppTab)` (chạy được trên iOS 17; build bằng SDK 26 thì tự có Liquid Glass). Không dùng `Tab(...)` vì API này cần iOS 18. Thứ tự `favourite`, `home`, `search`; mặc định `home`. Mỗi tab bọc `NavigationStack` riêng, `navigationTitle` + `.toolbarTitleDisplayMode(.inlineLarge)`.
- `MiniPlayerSlot`: iOS 26 dùng `.tabViewBottomAccessory`, iOS 17–18 dùng `safeAreaInset(edge: .bottom)` trên nội dung mỗi tab. Khi không có item đang phát (luôn đúng ở M1) thì **không hiện gì**, kể cả capsule rỗng của accessory. Dùng biến thể có `isEnabled` nếu SDK có; nếu không thì chỉ gắn modifier khi có nội dung.
- Model: `OnboardingModel`, `CategorySelectionModel`, `HomeModel` là `@MainActor @Observable final class`. `HomeModel` phụ thuộc `protocol HomeDataSource` trả struct Swift (`PodcastCard`, `LiveRowItem`…). Adapter thật map từ type Kotlin của `HomeFeed`; unit test dùng fake. View không giữ object Kotlin.
- State của mỗi section: `enum SectionState<T> { loading, loaded([T]), empty, failed }`. Section Live giữ `[[LiveRowItem]]` đã `chunked(3)`.
- `Design/`: Color Set `Primary #184BB4`, `Secondary #4A7DE7`, `TextTitle #39375B` (có biến thể Dark); chữ dùng màu semantic của hệ thống (`.primary`, `.secondary`) và Dynamic Type. Hỗ trợ cả Light và Dark. Riêng nền các trang onboarding giữ màu cố định của Android. Shimmer = `.redacted(reason: .placeholder)` + modifier shimmer tự viết.
- Analytics: `LogAnalyticsTracker` (Swift, implement `AnalyticsTracker`) ghi `Logger(subsystem: "tss.t.podcast", category: "Analytics")`, dạng `analytics screen=Onboarding CurrentPage=2` và `analytics event=OnboardingFinished screen=Onboarding`. Firebase thay vào sau.
- Log chung: `Logger(subsystem: "tss.t.podcast", category: "M1")`, không log header, credentials hay URL đầy đủ (chỉ host).

### 4.4 Ảnh và ATS (features-spec §2 "Ảnh", setup-and-build §3.3)

- `ArtworkLoader` (actor, không thêm thư viện ngoài): `URLSession` riêng với `URLCache` (memory 50 MB, disk 200 MB trong `Caches/`) cộng `NSCache` cho ảnh đã decode. Mỗi `URLRequest` đặt `User-Agent = SharedConstants.USER_AGENT_WEB_VALUE`. `ArtworkImage(url:)` là View dùng loader, có placeholder.
- URL `http://` → đổi thành `https://` trước khi gửi. Lỗi (kể cả `https` không chạy được) → placeholder, **không** thử lại bằng `http`. URL `nil`/blank → placeholder, không gửi request.
- `Info.plist` **không** có `NSAllowsArbitraryLoads` và không có `NSExceptionDomains`. Mỗi lần ảnh lỗi ghi log `artwork_failed host=<host>`; developer đo tỷ lệ ảnh `http://` và tỷ lệ lỗi trên một lần tải Home thật, ghi vào `progress.md`. Nếu tỷ lệ lỗi > 10% thì thêm bullet vào handoff (image proxy HTTPS cần cloud resource, việc của owner).
