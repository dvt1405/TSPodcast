## 1. Mục tiêu

Cuối M2, người dùng mở được **Podcast detail** thật từ Home và từ Search, thấy danh sách episode, và **tìm kiếm** podcast/nhạc như trên Android. Cụ thể:

1. `shared` có `PodcastDetailFeed` (E10 và E11 chạy song song, chỉ E10 quyết định thành công/lỗi, retry và cache 15 phút theo `feedId` như Android, lọc explicit theo D6) và `SearchFeed` (E7 "Tất cả", E8 "Nhạc", blacklist, `clean=true` + lọc explicit theo D6, query rỗng không gửi request, trending theo danh mục cho chip E9). Tất cả có unit test trong `commonTest`.
2. App iOS: màn `PodcastDetailView` thay cho stub M1: header (cover, tiêu đề, mô tả HTML → text có link bấm được), danh sách episode (ảnh, tiêu đề, ngày · thời lượng, mô tả 3 dòng), các trạng thái loading (shimmer) / empty / lỗi (alert "Tải lại"/"Huỷ" rồi lỗi inline có "Tải lại") / explicit bị ẩn.
3. Tap một episode → gửi **toàn bộ playlist + vị trí** sang một seam phát nhạc `PlaybackController`. M2 dùng bản stub chỉ ghi log và lưu request cuối; Player thật (AVFoundation) là M3.
4. Tab Tìm kiếm thay màn rỗng của M1: ô tìm kiếm (`.searchable`) debounce 200 ms, Return/Search chạy ngay; chip chế độ **Tất cả / Nhạc** luôn hiện, đổi chế độ thì tìm lại ngay; khi chưa nhập có gợi ý và chip danh mục (E9); kết quả, rỗng, lỗi, loading; tap kết quả → Detail; tap danh mục → danh sách podcast thịnh hành của danh mục đó ([Sửa]) → Detail.
5. Điều hướng đúng features-spec §1: Home → Detail (zoom transition trên iOS 18+), Search → Detail, mỗi tab giữ `NavigationStack` riêng.
6. Chuỗi mới có trong `Localizable.xcstrings` (vi nguồn, en đủ). XCUITest phủ mọi luồng tương tác mới; toàn bộ bộ test M1 vẫn xanh.

## 4. Quyết định kỹ thuật cho M2 (developer không cần hỏi lại)

### 4.1 Logic dùng chung mới trong `shared`

- `tss.t.shared.detail.PodcastDetailFeed` (property `podcastDetailFeed` của `SharedGraph`):
  - `suspend fun load(feedId: Long): TSDataState<PodcastDetail>`; gọi `getEpisodeByFeedId(id)` và `getPodcastByFeedID(id)` **song song** (`coroutineScope { async … }`), dùng nguyên retry + cache 15 phút của hai use case M0.
  - E10 `Error` → trả `Error` với exception của E10 (E11 ra sao cũng vậy). E10 `Success` → `Success(PodcastDetail)`; E11 lỗi thì `feed = null`, không làm hỏng kết quả.
  - `data class PodcastDetail(val episodes: List<Episode>, val feed: Feed?, val hiddenExplicitCount: Int, val isExplicitFeedHidden: Boolean)`.
  - D6, khi `AllowExplicitContent == false`: bỏ `Episode.explicit == 1` (đếm vào `hiddenExplicitCount`); nếu E11 `Success` và `feed.explicit == true` thì `episodes = emptyList()`, `isExplicitFeedHidden = true`. Khi cờ `true`: không bỏ gì. Không lọc blacklist ở đây (giống Android: feed đã qua blacklist ở màn trước).
- `tss.t.shared.search.SearchFeed` (property `searchFeed` của `SharedGraph`), `enum class SearchMode { All, Music }`:
  - `suspend fun search(query: String, mode: SearchMode): TSDataState<List<Feed>>`: trim; rỗng → `Success(emptyList())`, **0 request**. `All` → `SearchPodcasts` (E7 tham số như §3.2); `Music` → `SearchMusicFeeds` (E8). Blacklist giữ như M0. D6 khi `AllowExplicitContent == false`: gửi `clean=true` và bỏ `feed.explicit == true` sau blacklist; khi `true`: **không gửi** tham số `clean` (PodcastIndex coi `clean` là cờ có mặt, gửi `clean=false` vẫn lọc) và không bỏ gì.
  - `suspend fun categoryPodcasts(categoryId: Int): TSDataState<List<Podcast>>`: `GetTrendingPodcasts(max = 100, since = now − 7 ngày (604800 s), lang = "vi", cat = "<id>")`, nên có sẵn blacklist, cache memory + đĩa 15 phút (key `cachedTrending_<id>`). D6: bỏ `Podcast.explicit == 1` (E1 không trả field `explicit` nên trên thực tế không bỏ gì, giống giới hạn đã ghi ở M1). Đo thực tế 30/10/2026 với `lang=vi`: Arts 20, News 33, Business 39, Technology 10 kết quả.
- Không đổi `PodcastIndexApi`, `RetryPolicy`, use case M0 trừ khi cần thêm tham số; mọi thay đổi phải giữ test M0/M1 xanh.
- Swift gọi qua bridge `async` (không SKIE, quyết định M0). Kotlin enum `SearchMode` export sang Swift; phía Swift đặt tên type UI khác nếu trùng (ví dụ `SearchScope`).

### 4.2 Cấu trúc app iOS

- Thư mục mới/đổi trong `iosApp/TSPodcast/`:
  - `Detail/`: `PodcastRoute`, `PodcastDetailDataSource` (protocol trả struct Swift) + `SharedPodcastDetailDataSource` (adapter `PodcastDetailFeed`), `PodcastDetailModel`, `PodcastDetailView`, `EpisodeRow` (struct) + `EpisodeRowView`, `DescriptionText` (plain text → `AttributedString` có link). **Xoá** `PodcastDetailStubView`.
  - `Playback/`: `PlaybackRequest`, `protocol PlaybackController`, `LoggingPlaybackController` (§4.5).
  - `Search/`: `SearchDataSource` + `SharedSearchDataSource`, `SearchModel`, `SearchView` (thay `SearchRootView`), `SearchResultRow`, `CategoryPodcastsModel`, `CategoryPodcastsView`.
- Model là `@MainActor @Observable final class`, phụ thuộc protocol data source trả struct Swift (`EpisodeRow`, `SearchResultItem`, `PodcastCard`…). View không giữ object Kotlin. Adapter là `final class …: @unchecked Sendable` giữ reference bất biến tới object Kotlin (như `HomeFeedDataSource`), map Kotlin → Swift, log lỗi theo **tên type**.
- `PodcastRoute: Hashable, Sendable` là giá trị duy nhất cho `navigationDestination(for: PodcastRoute.self)`; đặt destination ở cả stack Home và stack Search. Home map `PodcastCard` → `PodcastRoute` (thêm field cần thiết vào `PodcastCard` nếu thiếu, ví dụ `feedImage` để fallback ảnh).
- `MainTabView` sở hữu `SearchModel` (`@State`, tạo bởi `AppEnvironment.makeSearchModel()`), và `path` riêng cho stack Search (như `homePath`).
- Zoom transition Home → Detail (features-spec §5, M1 đã dời sang đây): `if #available(iOS 18, *)` thì `.matchedTransitionSource(id:in:)` trên artwork của card Home và `.navigationTransition(.zoom(sourceID:in:))` trên Detail; iOS 17 dùng push mặc định.
- `EpisodeRow`: `id`, `title`, `summary` (HTML → plain qua `HtmlText.toPlainText`), `imageURL` (`Episode.getImageUrl()`: `image` trim, rỗng thì `feedImage`), `referer` (`episode.link`, `nil` khi rỗng), `publishedAt: Date?` (`datePublished` giây, `0` → `nil`), `durationSeconds`, `enclosureURL`, `enclosureType` (cần cho M3). Dòng phụ = ngày (`Date.FormatStyle` theo locale, ví dụ dạng `.dateTime.day().month(.abbreviated).year()`) · thời lượng (`Duration.UnitsFormatStyle`, chỉ giờ + phút, `.abbreviated`); thiếu phần nào thì bỏ phần đó và dấu " · "; `duration ≤ 0` → không hiện thời lượng; dưới 1 phút → "1 phút"/"1 min" (làm tròn lên).
- `DescriptionText`: nhận plain text, phát hiện URL bằng `NSDataDetector(.link)`, trả `AttributedString` có `.link`; `Text(attributed)` bấm link mở Safari (hành vi mặc định của SwiftUI). Thay cho `linkify` của Android.
- Log: `Logger(subsystem: "tss.t.podcast", category: "M2")` cho detail/search (`detail_failed type=…`, `search_failed mode=… type=…`); **không** log query thô (có thể chứa thông tin cá nhân), chỉ độ dài (`length=7`). Không log header/credentials/URL đầy đủ.

### 4.3 Search: debounce, submit, huỷ

- `SearchModel` nhận `debounce: Duration = .milliseconds(200)` và `clock: any Clock<Duration>` (inject để unit test không phụ thuộc thời gian thật).
- API: `queryChanged(_ text: String)`, `submit()`, `select(mode:)`, `retry()`; state `phase: .idle | .loading | .results([SearchResultItem]) | .empty | .failed` kèm `query`/`mode` của kết quả đang hiện (để header "… cho: %@" đúng với kết quả, không phải chữ đang gõ).
- `queryChanged`: huỷ task debounce đang chờ; trim rỗng → huỷ request đang chạy, `phase = .idle`, 0 request; còn lại → task mới ngủ `debounce` trên `clock` rồi tìm.
- `submit()`: huỷ debounce đang chờ, tìm ngay (nếu cặp (query, mode) khác request gần nhất).
- `select(mode:)`: cùng chế độ → không làm gì; khác → đổi chế độ và, nếu query không rỗng, tìm **ngay** (không debounce).
- Mỗi request có token tăng dần; kết quả chỉ được ghi nếu token còn là token mới nhất (request cũ xong muộn không ghi đè). Request mới huỷ `Task` của request cũ.

### 4.4 Ảnh episode có `Referer`

- `ArtworkLoader.image(for:referer:)` (tham số `referer: String? = nil`), `ArtworkImage(url:referer:)`. Khi có referer: request đặt header `Referer` (giữ `User-Agent` của M1). Cache vẫn theo URL ảnh (đã nâng https). Mọi lời gọi cũ không đổi hành vi. Android: `EpisodeWidget` `addHeader(REFERER_KEY, episode.link)`.
